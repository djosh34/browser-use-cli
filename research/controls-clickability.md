## What Chrome DevTools MCP reports

The tool description says `take_snapshot` is based on the accessibility tree and gives each listed node a UID. It describes verbose mode as all information in the full accessibility tree ([snapshot.ts lines 12-44](https://github.com/ChromeDevTools/chrome-devtools-mcp/blob/882f93e9a8809fe88eced35d793951fb456b7117/src/tools/snapshot.ts#L12-L44)). The implementation makes that precise. Both modes call Puppeteer's accessibility snapshot with iframes included. Normal mode passes `interestingOnly: true`; verbose passes `false` ([TextSnapshot.ts lines 47-59](https://github.com/ChromeDevTools/chrome-devtools-mcp/blob/882f93e9a8809fe88eced35d793951fb456b7117/src/TextSnapshot.ts#L47-L59)).

Puppeteer obtains `Accessibility.getFullAXTree`. With `interestingOnly: false`, it serializes every returned AX node. With the default, it flattens nodes outside its "interesting" set while retaining their selected descendants ([Accessibility.ts lines 241-365](https://github.com/puppeteer/puppeteer/blob/88b517ab3beb4a237b541cd18ada98ba43de71a7/packages/puppeteer-core/src/cdp/Accessibility.ts#L241-L365)). Despite the tool's "all possible information" wording, verbose changes node filtering only. Puppeteer's serializer still selects a fixed set of AX fields ([Accessibility.ts lines 602-708](https://github.com/puppeteer/puppeteer/blob/88b517ab3beb4a237b541cd18ada98ba43de71a7/packages/puppeteer-core/src/cdp/Accessibility.ts#L602-L708)), and MCP omits backend and loader IDs from text output ([SnapshotFormatter.ts lines 129-165](https://github.com/ChromeDevTools/chrome-devtools-mcp/blob/882f93e9a8809fe88eced35d793951fb456b7117/src/formatters/SnapshotFormatter.ts#L129-L165)). "Interesting" does not mean actionable. It includes landmarks, focusable or editable nodes, live or busy content, modal nodes, semantic controls, and named leaf content. It excludes ignored or hidden AX nodes ([Accessibility.ts lines 521-599](https://github.com/puppeteer/puppeteer/blob/88b517ab3beb4a237b541cd18ada98ba43de71a7/packages/puppeteer-core/src/cdp/Accessibility.ts#L521-L599)). The normal test fixture contains a button and textbox, while the verbose fixture also contains ignored structural nodes and an `InlineTextBox` ([expected output lines 334-452](https://github.com/ChromeDevTools/chrome-devtools-mcp/blob/882f93e9a8809fe88eced35d793951fb456b7117/tests/McpResponse.test.js.snapshot#L334-L452)). Verbose therefore means the unfiltered AX tree. It does not mean an expanded clickable-only set.

MCP assigns a UID to every serialized node and maps it to the AX node's backend DOM node ID. It reuses a UID only while loader ID and backend node ID remain the same ([TextSnapshot.ts lines 64-109](https://github.com/ChromeDevTools/chrome-devtools-mcp/blob/882f93e9a8809fe88eced35d793951fb456b7117/src/TextSnapshot.ts#L64-L109)). Puppeteer maps an AX text node to its parent element when resolving a handle ([Accessibility.ts lines 617-636](https://github.com/puppeteer/puppeteer/blob/88b517ab3beb4a237b541cd18ada98ba43de71a7/packages/puppeteer-core/src/cdp/Accessibility.ts#L617-L636)). The click tool accepts any snapshot UID. It does not first require an actionable role ([input.ts lines 84-120](https://github.com/ChromeDevTools/chrome-devtools-mcp/blob/882f93e9a8809fe88eced35d793951fb456b7117/src/tools/input.ts#L84-L120)). A replaced node fails resolution as stale rather than being matched to a similar new node ([McpPage.ts lines 685-713](https://github.com/ChromeDevTools/chrome-devtools-mcp/blob/882f93e9a8809fe88eced35d793951fb456b7117/src/McpPage.ts#L685-L713)).

## What click checks

MCP delegates ordinary clicks to `handle.asLocator().click()`. It special-cases an AX `option` by filling the owning single-select after checking the select, option, and optgroup disabled states ([input.ts lines 46-81](https://github.com/ChromeDevTools/chrome-devtools-mcp/blob/882f93e9a8809fe88eced35d793951fb456b7117/src/tools/input.ts#L46-L81)). Puppeteer's locator waits for some viewport intersection, a stable bounding box, and an enabled native form control ([locators.ts lines 323-428](https://github.com/puppeteer/puppeteer/blob/88b517ab3beb4a237b541cd18ada98ba43de71a7/packages/puppeteer-core/src/api/locators/locators.ts#L323-L428)). Its enabled check only recognizes six native element names and tests their own `disabled` attribute. It does not test `aria-disabled`, `inert`, or inherited disabled state such as a disabled fieldset ([locators.ts lines 287-320](https://github.com/puppeteer/puppeteer/blob/88b517ab3beb4a237b541cd18ada98ba43de71a7/packages/puppeteer-core/src/api/locators/locators.ts#L287-L320)).

The element click then scrolls for full intersection, takes the center of the first client rectangle clipped to the frame, and sends a mouse click ([ElementHandle.ts lines 727-776](https://github.com/puppeteer/puppeteer/blob/88b517ab3beb4a237b541cd18ada98ba43de71a7/packages/puppeteer-core/src/api/ElementHandle.ts#L727-L776), [lines 1164-1223](https://github.com/puppeteer/puppeteer/blob/88b517ab3beb4a237b541cd18ada98ba43de71a7/packages/puppeteer-core/src/api/ElementHandle.ts#L1164-L1223)). Neither path calls `elementFromPoint` or otherwise verifies that the target owns the click point. A covered target or one with `pointer-events: none` can pass these checks and cause another element to receive the event. MCP's success message means the mouse operation completed, not that the intended handler ran or had a meaningful effect. Its basic test checks that a button's inline handler changes text after a click, but does not exercise an overlay or hit test ([input.test.ts lines 33-59](https://github.com/ChromeDevTools/chrome-devtools-mcp/blob/882f93e9a8809fe88eced35d793951fb456b7117/tests/tools/input.test.ts#L33-L59)).

## CDP signals and their limits

`Accessibility.getFullAXTree` returns AX role, name, state, ignored reasons, and an optional backend DOM node ID ([Accessibility.pdl lines 178-241](https://github.com/ChromeDevTools/devtools-protocol/blob/1cab90fb8d2066eb9f969da4f9b9bc7c50889af2/pdl/domains/Accessibility.pdl#L178-L241)). It is the better source for semantic controls and accessible names. Ignored reasons include `inertElement`, `inertSubtree`, `notRendered`, and `notVisible` ([Accessibility.pdl lines 114-176](https://github.com/ChromeDevTools/devtools-protocol/blob/1cab90fb8d2066eb9f969da4f9b9bc7c50889af2/pdl/domains/Accessibility.pdl#L114-L176)). The full AX tree is still not the full DOM, and neither normal nor verbose mode applies a viewport test.

`DOMSnapshot.captureSnapshot` returns the flattened DOM, layout bounds, requested computed styles, optional paint order, and a sparse `isClickable` flag ([DOMSnapshot.pdl lines 195-246](https://github.com/ChromeDevTools/devtools-protocol/blob/1cab90fb8d2066eb9f969da4f9b9bc7c50889af2/pdl/domains/DOMSnapshot.pdl#L195-L246)). Blink sets that flag solely from `WillRespondToMouseClickEvents()` ([agent lines 537-538](https://chromium.googlesource.com/chromium/src/+/c52f26bf4995863398cbdd1a7cabc3dd45aad973/third_party/blink/renderer/core/inspector/inspector_dom_snapshot_agent.cc#537)). The base check rejects native disabled form controls, then accepts editable nodes or nodes with their own `click`, `mousedown`, `mouseup`, or `DOMActivate` listener ([node.cc lines 3462-3467](https://chromium.googlesource.com/chromium/src/+/c52f26bf4995863398cbdd1a7cabc3dd45aad973/third_party/blink/renderer/core/dom/node.cc#3462), [event_util.cc lines 18-23](https://chromium.googlesource.com/chromium/src/+/c52f26bf4995863398cbdd1a7cabc3dd45aad973/third_party/blink/renderer/core/events/event_util.cc#18)). Native classes add cases such as links and inputs ([anchor lines 531-533](https://chromium.googlesource.com/chromium/src/+/c52f26bf4995863398cbdd1a7cabc3dd45aad973/third_party/blink/renderer/core/html/html_anchor_element.cc#531), [input lines 1716-1722](https://chromium.googlesource.com/chromium/src/+/c52f26bf4995863398cbdd1a7cabc3dd45aad973/third_party/blink/renderer/core/html/forms/html_input_element.cc#1716)).

`isClickable` is a candidate hint, not a hit test. It misses event delegation, keyboard shortcuts, pointer-only or touch-only listeners, canvas regions, and behavior inferred by application code. It does not test viewport position, occlusion, `pointer-events`, `aria-disabled`, or whether a handler will do useful work. AX roles have the opposite blind spot: a clickable `div` may have no useful role or accessible name. Hidden and inert nodes can be absent or ignored in AX while still present in DOMSnapshot. Offscreen candidates can be valid after scrolling. Every signal can become stale after DOM replacement.

## Small Go design

Use CDP directly and keep discovery separate from action checks.

For `controls`, the smallest credible default is named AX nodes with an interactive role, or an AX focusable or editable state. Return role, name, relevant states, frame, and backend node ID. Label these as candidates. Do not port Puppeteer's broader "interesting" filter because it intentionally includes content and landmarks.

A useful `--verbose` can add unnamed candidates, ignored/disabled diagnostics, and DOMSnapshot `isClickable` candidates that the semantic pass missed. Mark each candidate's source. This is more useful for a controls command than dumping every AX text node. The separate `read` command can own full page text.

At click time, resolve the backend node again, reject a detached node, apply the chosen disabled policy, scroll only under the chosen offscreen policy, require a nonempty box, and hit-test the intended point. Report that input was dispatched, not that the page completed an intended outcome. Keyboard and other non-mouse actions need their own commands and checks.

The owner still needs to decide whether default output includes offscreen controls, whether click auto-scrolls, whether disabled and `aria-disabled` controls are omitted or shown with state, and whether verbose pays the extra DOMSnapshot cost. Those choices should not be hidden inside the candidate filter.
